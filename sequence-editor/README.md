# 序列帧动画编辑器

本地 Web 工具，用于浏览和播放各角色的序列帧动画（Walk / Harm / Hit / Death / Shoot 等动作）。

## 启动方法

### 方式一：双击启动脚本（推荐）
双击 `start.bat`，然后浏览器打开 <http://localhost:8765/>

### 方式二：命令行启动
```bash
python server.py
```
然后浏览器打开 <http://localhost:8765/>

## 功能

- **角色列表**：左侧列出全部 87 个角色，支持关键字搜索（可即时过滤）
- **动作切换**：选择角色后，顶部标签页显示该角色的全部动作（Walk、Harm、Hit、Death、Shoot 等），点击切换
- **动画播放**：进入角色自动播放；`▶/⏸` 按钮或空格键播放/暂停
- **帧控制**：上一帧/下一帧（或 ←/→ 方向键）、帧进度条拖动、回到第一帧
- **速度调节**：1 ~ 30 fps 速度滑块，可调整播放快慢
- **循环开关**：勾选后播放到最后一帧自动回到开头循环
- **洋葱皮**：开启后叠加显示上一帧的半透明影像，方便观察动作轨迹
- **缩放**：适应窗口 / 50% / 100% / 200% / 300%
- **帧带**：底部显示当前动作全部帧，点击任意帧跳转
- **信息栏**：显示角色名、动作名、当前帧/总帧数、图片尺寸
- **导入新动作**：动作标签栏的「＋ 导入动作」按钮，直接在界面里选择图片即可为新动作创建序列帧（详见下文）
- **导出 GIF**：把当前动作导出为透明背景的 GIF 动图
- **导出雪碧图**：把当前动作所有帧拼成一张 PNG 雪碧图（便于整体查看/发布）
- **重心点（Pivot）**：设置一个全局对齐锚点（⚓ 按钮进入设置模式，点击画布或手动输入 X/Y 坐标，支持 ◂/▸ 像素微调），用于导出图集时保证各帧对齐
- **导出图集（Atlas）**：以**角色为单位**导出全部动作，自动裁剪每帧空白，以重心点对齐，生成一张 PNG 图集 + 一个 JSON 元数据文件（帧位置、重心偏移、按动作分组）

## 如何新增动作

给某个角色添加新动作（如 Jump、Skill、Attack 等），有**两种方式**：

### 方式一：界面导入（推荐）
1. 在左侧选中目标角色
2. 点动作标签栏右侧的「**＋ 导入动作**」
3. 输入动作名（字母/数字/下划线/中文，不超过 40 字符）
4. 选择帧图片（可多选，按顺序排列，自动显示预览）
5. 点「上传」，完成后自动切换到新动作并播放

### 方式二：手动放文件
1. 把新动作的序列帧图片放进该角色文件夹的 `PNG/` 目录
2. 按命名规则命名：`角色名-动作名_帧号.png`（帧号从 `0` 开始连续递增）
   - 示例：给 `abo` 添加 `Skill` 动作 →
     `abo/PNG/abo-Skill_0.png`、`abo-Skill_1.png`、`abo-Skill_2.png` …
3. 刷新浏览器页面（F5），新动作会自动出现在该角色的动作标签栏

### 命名规则细节
- 文件名格式：`角色名-动作名_帧号.png`
- 动作名会直接作为标签显示，解析时**不区分大小写**（`walk` / `Walk` 都会识别），但会被当作**两个不同的动作标签**，建议统一命名
- 帧号必须从 `0` 开始，会自动按数字排序，帧数不限（1 张也支持，只是不自动播放）
- 若动作名不在预设顺序里（Walk/Run/Harm/Hit/Death/Shoot/Attack/Skill/Cast/Idle），会按字母序自动排在后面
- 想让自定义动作排在最前面，可修改 `server.py` 中的 `ACTION_ORDER` 列表

## 导出图集（Atlas）使用说明

「📦 导出图集」会把当前角色的**全部动作**导出为一个 ZIP 压缩包 `角色名-atlas.zip`，内含两个文件：
- `角色名-atlas.png` — 所有动作的帧裁剪掉空白后拼成的一张图（尺寸自动控制在 **2048×2048 以内**，且宽高均为 **4 的倍数**，便于渲染/压缩对齐）
- `角色名-atlas.json` — 元数据：每帧在图集中的位置、重心偏移（按动作分组）

```json
{
  "character": "abo",
  "pivot": { "x": 150, "y": 280 },
  "canvasSize": { "w": 300, "h": 400 },
  "atlasSize": { "w": 1024, "h": 512 },
  "frameCount": 20,
  "actions": {
    "Walk": {
      "count": 7,
      "frames": [
        { "name": "abo-Walk_0", "frame": { "x": 0, "y": 0, "w": 45, "h": 60 },
          "pivot": { "x": 25, "y": 58 },
          "sourceSize": { "w": 300, "h": 400 },
          "sourceBounds": { "x": 122, "y": 220, "w": 45, "h": 60 } }
      ]
    }
  }
}
```

在游戏里渲染某帧时：
1. 从 `atlas.png` 中截取 `frames[i].frame` 指定的区域
2. 以 `frames[i].pivot` 为锚点放置（绘制位置 = 目标坐标 - pivot 偏移）

因为所有帧都以同一个全局重心点对齐，裁剪后动画不会发生位置抖动。

> 提示：重心点是全局唯一的，切换角色/动作都保持不变；未手动设置时默认为画布中心。

## 在新电脑上继续开发

本工具是**纯源码**，可直接复制到新电脑继续开发。默认的 `server.exe` 只是源码的「打包快照」，改代码后要跑源码而不是 exe。

### 1. 需要的环境
- **Python 3**（服务器本身只用标准库，**无需安装任何第三方包**就能跑起来）
- 想重新打包 exe：再装 `pyinstaller`（`pip install pyinstaller`）
- 想重新生成 `角色形象对照表.xlsx`：再装 `openpyxl` 和 `Pillow`（`pip install openpyxl pillow`）

### 2. 日常开发 / 测试流程
1. 用任意编辑器修改 `server.py` / `index.html` / `style.css` / `app.js`
2. 在 `sequence-editor/` 目录运行源码：
   ```bash
   python server.py
   ```
3. 浏览器打开 <http://localhost:8765/> 验证改动

> ⚠️ 注意：
> - **改完代码必须用 `python server.py` 跑源码**，双击 `server.exe` 运行的是旧代码快照，看不到你的改动
> - `server.exe` 和 `python server.py` 占用同一个端口 `8765`，**不要同时运行**，会端口冲突
> - 前端文件（html/css/js）改动后，浏览器按 **F5** 刷新即可生效（服务器在 `/api/manifest` 接口已设为不缓存）

### 3. 修改后重新打包 exe
```bash
cd sequence-editor
pip install pyinstaller
pyinstaller --onefile --name server --clean server.py
copy dist\server.exe ..\server.exe
```
把生成的 `server.exe` 放到**根目录**（和角色文件夹同一层），目标电脑即可双击使用。

### 4. 修改后重新打整包 ZIP
```bash
python 上级目录的 make_portable_zip.py
```
（该脚本会排除 `.venv`、`build`、`dist`、`__pycache__` 等，PNG 图片不压缩以加快打包速度。）

### 5. 代码结构速览（改哪里）
| 想改什么 | 改哪个文件 |
| --- | --- |
| 动作显示顺序 / 扫描逻辑 / 上传接口 | `server.py` |
| 页面结构（加按钮、弹窗） | `index.html` |
| 外观样式 | `style.css` |
| 前端逻辑（播放、导入、导出、量化算法） | `app.js` |
| 导出 GIF 的编码 | `vendor/omggif.js` + `app.js` 里的量化/编码函数 |
